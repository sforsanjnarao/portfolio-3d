How it fits together

The agent never gets to choose whose data it reads. Its tools are built for one user on the server, before the model sees a single message.

How the assistant stays in its lane

  1. 01

    You ask a question

    The API route reads who you are from the server session, never from the request body.

  2. 02

    Tools are built for you

    The agent’s tools, like list_my_breaches and get_risk_summary, are created with your user id baked in.

  3. 03

    The model picks tools, not users

    It can choose which tool to call, but the user id is never one of its inputs, so it has no way to ask for someone else’s data.

  4. 04

    Breaches in plain words

    Raw breach records go through a structured-output call with a strict JSON schema, which comes back as a plain explanation with severity and what to do.

The hard part

Letting an AI agent read private data without trusting the model. Prompt rules like “only look at this user” can be talked around.

So the boundary lives in the code instead: the user id is bound when the tools are built, so the model physically can’t query another user’s rows, whatever it’s asked.
